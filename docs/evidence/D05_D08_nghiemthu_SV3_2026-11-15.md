## 1. D-05 — `vault_admin` NOSUPERUSER (6 phép thử thật)

### 1.1. Thuộc tính role

```bash
docker compose exec -T postgres psql -U postgres -d encryption_db -c \
  "SELECT rolname, rolsuper, rolcreatedb, rolcreaterole, rolinherit FROM pg_roles WHERE rolname IN ('vault_admin','app_writer','app_user') ORDER BY rolname;"
```

```
   rolname   | rolsuper | rolcreatedb | rolcreaterole | rolinherit
-------------+----------+-------------+---------------+------------
 app_user    | f        | f           | f             | t
 app_writer  | f        | f           | f             | t
 vault_admin | f        | f           | t             | f
(3 rows)
```

**ĐẠT** — đúng kỳ vọng `f/f/t/f` của biên bản SV2. `app_writer` tồn tại và NOLOGIN.

### 1.2. `vault_admin` không SELECT trực tiếp được

```bash
docker compose exec -T -e PGPASSWORD=local_vault_admin_password postgres \
  psql -h 127.0.0.1 -U vault_admin -d encryption_db -c "SELECT count(*) FROM sensitive_records;"
```

```
ERROR:  permission denied for table sensitive_records
```

**ĐẠT** — `NOINHERIT` chặn truy cập trực tiếp đúng như thiết kế.

### 1.3. Phép thử leo thang `SET ROLE` — PHÁT HIỆN CLAIM SAI

```bash
docker compose exec -T -e PGPASSWORD=local_vault_admin_password postgres \
  psql -h 127.0.0.1 -U vault_admin -d encryption_db -c \
  "SET ROLE app_writer; SELECT count(*) AS doc_duoc_qua_set_role FROM sensitive_records;"
```

```
SET
 doc_duoc_qua_set_role
-----------------------
                     0
(1 row)
```

```bash
docker compose exec -T postgres psql -U postgres -d encryption_db -c \
  "SELECT pg_has_role('vault_admin','app_writer','SET') AS can_set, pg_has_role('vault_admin','app_writer','USAGE') AS can_inherit;"
```

```
 can_set | can_inherit
---------+-------------
 t       | f
(1 row)
```

**Kết quả: `vault_admin` ĐỌC ĐƯỢC bảng qua `SET ROLE app_writer`.** Claim "không đọc được bảng dữ liệu" trong biên bản SV2 (mục 1.3 và Kết luận D-05) là **không đúng**. Nguyên nhân: `GRANT app_writer TO vault_admin WITH ADMIN OPTION` trong `api/sql/00-create-roles.sql` để `SET TRUE` mặc định (PostgreSQL 16); `NOINHERIT` chỉ chặn kế thừa tự động, không chặn `SET ROLE`. Đối chiếu tài liệu: <https://www.postgresql.org/docs/current/role-membership.html>.

### 1.4. Cách sửa — đã kiểm chứng trên stack này

```bash
docker compose exec -T postgres psql -U postgres -d encryption_db -c \
  "GRANT app_writer TO vault_admin WITH ADMIN TRUE, SET FALSE;"
# can_set=false
# SET ROLE app_writer -> ERROR:  permission denied to set role "app_writer"
# vault read database/creds/app-role -> dynamic role vẫn SELECT được: dynamic_ok
docker compose exec -T postgres psql -U postgres -d encryption_db -c \
  "GRANT app_writer TO vault_admin WITH ADMIN TRUE, SET TRUE;"   # khôi phục trạng thái commit
# can_set_restored=true
```

`SET FALSE` chặn leo thang mà **không phá** khả năng `GRANT app_writer` cho dynamic role của Vault plugin (ADMIN giữ nguyên). Cú pháp đúng có dấu phẩy; `WITH ADMIN OPTION SET FALSE` bị lỗi syntax. PostgreSQL 15 (stack `infrastructure/` của SV1) không có `SET` option — ở đó bỏ membership và dựa vào `CREATEROLE` là đủ để grant.

**Khuyến nghị:** áp dụng `SET FALSE` vào `00-create-roles.sql` (stack gốc PG16), hoặc ghi risk-accepted bằng văn bản nếu giữ nguyên; sửa claim trong báo cáo/biên bản trước khi đóng D-05.

**Cập nhật cuối ngày 15/11 (SV3):** khuyến nghị trên đã được thực hiện trong commit SQL tách riêng `efeb7c4` trên nhánh `docs/nghiemthu-d05-d08-sv3`: `GRANT app_writer TO vault_admin WITH ADMIN TRUE, SET FALSE;` (PostgreSQL 16+; stack `infrastructure/` PG15 không mount `api/sql` nên không bị ảnh hưởng), kèm cập nhật regression test `test_vault_admin_sql_is_not_superuser`. SV3 dựng lại stack sạch từ chính file SQL đã sửa và nghiệm thu lại: `SET ROLE app_writer` bị từ chối, dynamic credential vẫn đọc/ghi được, revoke vẫn DROP ROLE.

## 2. D-08 — pool / worker / DEK cache / connection

### 2.1. Cấu hình thật trong container

```bash
docker compose exec -T api python -c "from app.config import settings; import os; print('pool_size=',settings.db_pool_size,'max_overflow=',settings.db_max_overflow,'dek_ttl=',settings.dek_cache_ttl_seconds,'dek_max=',settings.dek_cache_max_entries,'workers_env=',os.getenv('UVICORN_WORKERS'))"
```

```
pool_size= 20 max_overflow= 20 dek_ttl= 0 dek_max= 1024 workers_env= 2
```

**ĐẠT** — pool 20+20 (trần 40 connection/worker), cache DEK **tắt mặc định** nên T08 `min_decryption_version` vẫn có hiệu lực mỗi lần decrypt.
