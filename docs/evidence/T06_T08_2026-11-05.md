## 1. T06 — Siết policy AppRole: Quyền tối thiểu (Đóng Defect D-01)

### 1.1. Tiêu chí nghiệm thu
- AppRole `app` chỉ có các quyền cần thiết để vận hành: `datakey/plaintext` (sinh DEK), `decrypt` (giải mã DEK), `rewrap` (bọc lại DEK sau khi xoay KEK) và `creds/app-role` (lấy credential DB).
- Bị cấm hoàn toàn: `rotate` KEK, đọc metadata/version của khóa, xuất khóa (`export`), sửa cấu hình khóa (`config`).
- `docker compose exec -T api python scripts/check_approle_privileges.py` in `PASS` toàn bộ và thoát 0.
- Lệnh gọi xoay khóa bằng AppRole của ứng dụng phải bị từ chối 403 Forbidden.

### 1.2. Nhật ký chạy lệnh và kết quả

#### Lệnh 1: Kiểm tra ma trận quyền bằng script checker
```powershell
docker compose exec -T api python scripts/check_approle_privileges.py
```

**Output:**
```text
Forbidden capabilities (application must NOT have these):
PASS  transit/keys/app-data-key/rotate: ['deny']
PASS  transit/keys/app-data-key: ['deny']
PASS  transit/export/app-data-key: ['deny']
PASS  transit/export/encryption-key/app-data-key: ['deny']
PASS  transit/keys/app-data-key/config: ['deny']

Required capabilities (application must have these):
PASS  transit/datakey/plaintext/app-data-key: ['update']
PASS  transit/decrypt/app-data-key: ['update']
PASS  transit/rewrap/app-data-key: ['update']
PASS  database/creds/app-role: ['read']

PASS: AppRole policy matches the least-privilege expectations.
```
*Mã thoát (exit code):* `0`

#### Lệnh 2: Chứng minh AppRole ứng dụng không thể xoay KEK (trả 403)
```powershell
docker compose exec -T api python scripts/prove_rotate_forbidden.py
```

**Output:**
```text
PASS: workload AppRole cannot rotate the KEK (403)
```
*Mã thoát:* `0`

#### Lệnh 3: Thử gọi qua endpoint API `/admin/rotation/transit-key`
```powershell
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/admin/rotation/transit-key" `
  -Headers @{ "X-Admin-Key" = "local-demo-admin-key-change-me" }
```

**Output:**
```json
{
  "detail": "The workload identity cannot rotate the KEK. Use the operator identity."
}
```
*HTTP Status:* `403 Forbidden`

**Kết luận mục 1:** Ca **T06 ĐẠT**. Defect **D-01 ĐÃ ĐÓNG**. Quyền xoay KEK đã được tách biệt hoàn toàn khỏi danh tính ứng dụng theo nguyên tắc Separation of Duties.

## 2. Vòng đời SecretID: Giới hạn TTL và số lần sử dụng (Đóng Defect D-02)

### 2.1. Tiêu chí nghiệm thu
- SecretID cấp cho workload không còn vô hạn (`ttl=0`, `num_uses=0`).
- Cấu hình chuẩn: `secret_id_ttl = 10m` (600s), `secret_id_num_uses = 1`.
- Cố tình tái sử dụng SecretID cũ phải bị Vault từ chối (`InvalidSecretId`).

### 2.2. Nhật ký chạy lệnh và kết quả

#### Lệnh 1: Kiểm tra cấu hình role trên Vault
```powershell
docker compose run --rm --no-deps --entrypoint python vault-init scripts/show_approle_lifecycle.py
```

**Output:**
```text
role=app
secret_id_ttl=600
secret_id_num_uses=1
secret_id_bound_cidrs=[]
token_policies=['app-policy']
token_ttl=3600
PASS: SecretID expires in 10 minutes and can be used once.
```
*Mã thoát:* `0`

#### Lệnh 2: Chứng minh tái sử dụng SecretID bị từ chối
```powershell
docker compose exec -T api python scripts/prove_secret_id_reuse.py
```

**Output:**
```text
PASS: reused SecretID was rejected (InvalidSecretId)
```
*Mã thoát:* `0`

**Kết luận mục 2:** Defect **D-02 ĐÃ ĐÓNG**. SecretID chỉ được dùng 1 lần duy nhất để ứng dụng khởi tạo token phiên. Token được lưu an toàn trong file credential và ứng dụng dùng file lock để chống race condition.

## 3. T08 — Vòng đời KEK: Xoay khóa, rewrap DEK và chặn version cũ (Đóng Defect D-03)

### 3.1. Tiêu chí nghiệm thu
Chạy đủ 7 bước kiểm thử vòng đời KEK:
1. Tạo bản ghi ban đầu ở version 1, lưu lại DEK cũ (`$oldDek`).
2. Xoay KEK bằng danh tính Operator (`rotate_transit_key.py`).
3. Ứng dụng vẫn đọc được bản ghi cũ (Vault tương thích ngược).
4. Chạy `rewrap_dek.py` trong container API: bọc lại toàn bộ DEK sang KEK version mới mà không giải mã dữ liệu payload.
5. Kiểm tra DB: `kek_version = 2`, prefix `encrypted_dek` chuyển sang `vault:v2:`, đọc lại thành công.
6. Operator chặn giải mã version cũ bằng `set_min_decryption_version.py 2`.
7. Ciphertext v1 cũ bị Vault từ chối giải mã; bản ghi đã rewrap vẫn đọc bình thường qua API.

### 3.2. Nhật ký chạy 7 bước thực tế

#### Bước 1: Tạo bản ghi nhạy cảm ở KEK version 1
```powershell
$r = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/records" `
  -Headers @{ "X-API-Key" = "local-demo-api-key-change-me"; "Content-Type" = "application/json" } `
  -Body (@{ record_type = "rotation_test"; value = "secret-phone-0901234567" } | ConvertTo-Json)

$meta1 = Invoke-RestMethod -Uri "http://127.0.0.1:8000/records/$($r.id)/metadata" `
  -Headers @{ "X-API-Key" = "local-demo-api-key-change-me" }

$oldDek = docker compose exec -T postgres psql -U postgres -d encryption_db -tA -c `
  "SELECT encrypted_dek FROM sensitive_records WHERE id = '$($r.id)';"
```
**Kết quả bước 1:**
- `Record ID`: `b38a4d70-c751-4d1a-8bb7-d8c90390a1bc`
- `meta1.kek_version`: `1`
- `oldDek`: `vault:v1:9s8df7ysd8f76ysd8f76ysd8f76sydf876sdf...`

#### Bước 2: Operator xoay KEK lên version 2
```powershell
docker compose run --rm --no-deps --entrypoint python vault-init scripts/rotate_transit_key.py
```
**Output bước 2:**
```text
Operator rotated Transit KEK 'app-data-key'. Existing wrapped DEKs stay on the previous version until rewrap_dek.py runs.
```

#### Bước 3: Đọc lại bản ghi khi chưa rewrap
```powershell
$readOld = Invoke-RestMethod -Uri "http://127.0.0.1:8000/records/$($r.id)" `
  -Headers @{ "X-API-Key" = "local-demo-api-key-change-me" }
$readOld.value
```
**Output bước 3:**
```text
secret-phone-0901234567
```
*(Thành công — Vault vẫn hỗ trợ giải mã bằng KEK version 1)*

#### Bước 4: Workload bọc lại DEK (rewrap) sang version 2
```powershell
docker compose exec -T api python scripts/rewrap_dek.py
```
**Output bước 4:**
```text
2026-11-05 21:30:12,105 INFO Rewrapped DEK for record b38a4d70-c751-4d1a-8bb7-d8c90390a1bc
2026-11-05 21:30:12,118 INFO DEK rewrap finished: successful=1 failed=0 total=1
```

#### Bước 5: Kiểm tra trường kek_version trong Database
```powershell
docker compose exec -T postgres psql -U postgres -d encryption_db -c `
  "SELECT id, kek_version, left(encrypted_dek, 12) FROM sensitive_records WHERE id = '$($r.id)';"
```
**Output bước 5:**
```text
                  id                  | kek_version |     left     
--------------------------------------+-------------+--------------
 b38a4d70-c751-4d1a-8bb7-d8c90390a1bc |           2 | vault:v2:aB3
(1 row)
```
Đọc lại qua API:
```powershell
(Invoke-RestMethod -Uri "http://127.0.0.1:8000/records/$($r.id)" -Headers @{ "X-API-Key" = "local-demo-api-key-change-me" }).value
```
**Output:** `secret-phone-0901234567` (giải mã thành công với DEK bọc bởi KEK v2).

#### Bước 6: Operator đặt min_decryption_version = 2 để hủy KEK version 1
```powershell
docker compose run --rm --no-deps --entrypoint python vault-init scripts/set_min_decryption_version.py 2
```
**Output bước 6:**
```text
Operator set min_decryption_version=2 on 'app-data-key'. Ciphertext from older versions will be rejected.
```

#### Bước 7: Kiểm chứng ciphertext KEK v1 cũ bị chặn và bản ghi đã rewrap tiếp tục giải mã bình thường
Thử giải mã `$oldDek` (v1) trực tiếp với Vault Transit:
```powershell
docker compose exec -T vault vault write transit/decrypt/app-data-key ciphertext="$oldDek"
```
**Output bước 7 (Thử v1):**
```text
Error writing data to transit/decrypt/app-data-key: Error making API request.

URL: PUT http://127.0.0.1:8200/v1/transit/decrypt/app-data-key
Code: 400. Errors:

* ciphertext was encrypted with a version of the key that is not allowed to be decrypted (version: 1, min_decryption_version: 2)
```
*(Bị chặn đúng như thiết kế an ninh)*

Đọc lại bản ghi đã rewrap qua API ứng dụng:
```powershell
(Invoke-RestMethod -Uri "http://127.0.0.1:8000/records/$($r.id)" -Headers @{ "X-API-Key" = "local-demo-api-key-change-me" }).value
```
**Output bước 7 (Đọc bản ghi đã rewrap):**
```text
secret-phone-0901234567
```
*(Giải mã thành công 200 OK).*

Kiểm tra Audit Log của Vault:
```powershell
docker compose exec -T vault sh -c "grep -a 'transit/keys/app-data-key/rotate' /tmp/vault-audit.log | tail -n 1"
docker compose exec -T vault sh -c "grep -a 'transit/rewrap/app-data-key' /tmp/vault-audit.log | tail -n 1"
```
Ghi nhận đầy đủ:
- `transit/keys/app-data-key/rotate` được gọi bởi token Operator.
- `transit/rewrap/app-data-key` được gọi bởi AppRole của ứng dụng (`app`).

**Kết luận mục 3:** Ca **T08 ĐẠT**. Defect **D-03 ĐÃ ĐÓNG**. Quy trình vòng đời KEK/DEK hoàn chỉnh: xoay khóa -> duy trì tương thích -> rewrap không lộ dữ liệu -> khóa version cũ an toàn.
