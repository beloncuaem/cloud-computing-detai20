# T03/T04 — Phát hiện sửa ciphertext và tráo payload (31/10/2026)

Bản ghi terminal trên stack dự phòng (Vault dev + PostgreSQL 16 + API FastAPI). Cần chụp ảnh màn hình khi nộp.

## T03 — Sửa một byte ciphertext

- Tạo bản ghi `tamper_test`.
- Lật byte đầu của `ciphertext` bằng SQL.
- Gọi `GET /records/{id}`.

Kết quả:

```text
T03 record=90c55a35-dab0-4e9d-b382-829647e6091b
T03 HTTP status: 503
record.read|failure|{"reason": "decrypt_failed"}
record.create|success|{"record_type": "tamper_test", "encryption": "AES-256-GCM"}
```

## T04 — Tráo ciphertext/nonce/encrypted DEK giữa hai bản ghi

- Tạo bản ghi `aad_a` và `aad_b`.
- Chép toàn bộ payload mã hóa của A sang B, giữ nguyên `record_type` của B.
- Gọi `GET /records/{B}`.

Kết quả:

```text
T04 a=61398057-a6e7-4861-9b59-ad790a2f07a1 b=f3e62104-f9df-4125-b60c-06d1e43e4434
T04 HTTP status: 503
record.read|failure|{"reason": "decrypt_failed"}
```

## Kết luận

- AES-256-GCM từ chối ciphertext bị sửa (T03).
- AAD `record_id:record_type` ngăn tráo payload giữa hai bản ghi (T04).
- Audit ghi `record.read` / `failure` / `decrypt_failed`; không có plaintext trong log.
- Đã xóa bản ghi và audit event test sau khi chụp kết quả.
