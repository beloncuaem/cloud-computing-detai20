## 1. TLS trên đường truyền (đạt)

Kiến trúc: nginx là TLS terminator cho cả ba ranh giới — Vault `8200`, API `8443`, baseline `8444`. Vault giữ HTTP **nội bộ** trong network Docker (giới hạn lab D-04); biến thể production-intent dùng TLS native trong `infrastructure/vault/config/vault.hcl`.

```
$ curl -k -s -i https://localhost:8200/v1/sys/health
HTTP/1.1 200 OK
Server: nginx/1.27.5
Content-Type: application/json

$ curl -k -s -i https://localhost:8443/health
HTTP/1.1 200 OK
Server: nginx/1.27.5
{"status":"ok"}

$ openssl s_client -connect localhost:8443 -servername localhost -tls1_2 </dev/null
Protocol: TLSv1.2
    Cipher    : ECDHE-RSA-AES128-GCM-SHA256
    Verify return code: 21 (unable to verify the first certificate)

$ openssl s_client -connect localhost:8443 -servername localhost -tls1_3 </dev/null
Protocol: TLSv1.3
    Cipher    : TLS_AES_256_GCM_SHA384
```

`Verify return code: 21` là **đúng kỳ vọng lab**: CA tự ký (`infrastructure/certs/gen-certs.sh`) chưa nằm trong trust store của máy. Chain đã kiểm chứng riêng: `openssl verify -CAfile out/ca.crt out/{nginx,postgres,vault}.crt` → cả ba `OK`.

## 2. At-rest (đạt một phần — risk-accepted có văn bản)

```
$ docker compose exec -T postgres psql -U postgres -d encryption_db -t -c "SHOW ssl;"
 on

$ ... -c "SELECT ssl, version, count(*) FROM pg_stat_ssl JOIN pg_stat_activity USING (pid) WHERE usename IS NOT NULL GROUP BY 1,2;"
 ssl | version | count
-----+---------+-------
 t   | TLSv1.3 |     2
 f   |         |     2
```

Hai connection của API (2 worker) đi TLSv1.3 tới PostgreSQL; hai connection không SSL là Vault database plugin và psql quản trị.

**BitLocker (probe chỉ-đọc qua UAC, `manage-bde -status C:`):**

```
Volume C: [OS]
    Conversion Status:    Fully Decrypted
    Percentage Encrypted: 0,0%
    Encryption Method:    None
    Protection Status:    Protection Off
```

Ổ D: cũng `ProtectionStatus 0`. Theo quyết định đã duyệt ngày 16/11: **không tự bật BitLocker** (cần admin + lưu recovery key, rủi ro khoá máy). Hệ quả:

- Không đo cấu hình **C** (TLS + mã hoá volume); T14 giữ "đạt một phần" cho C.
- At-rest cấp volume ghi **risk-accepted**: dữ liệu nhạy cảm vẫn được bảo vệ ở cấp ứng dụng (envelope encryption, ciphertext trong DB) và trên đường truyền (TLS). Điều kiện đóng: bật BitLocker cho ổ chứa VHDX của Docker, hoặc chuyển PostgreSQL sang volume LUKS, rồi đo lại C.
- T13 ký **ĐẠT phần TLS**; phần at-rest cấp volume là giới hạn đã ghi nhận, không tuyên bố đạt.

## 5. D-05 trên volume dựng lại (đạt)

```
SELECT m.admin_option, m.set_option, m.inherit_option
FROM pg_auth_members m
WHERE m.roleid='app_writer'::regrole AND m.member='vault_admin'::regrole;
 t | f | f
```

`SET FALSE` có hiệu lực ngay từ initdb của stack TLS; `SET ROLE app_writer` bị từ chối (đã kiểm chứng ở biên bản D-05/D-08 ngày 15/11).
